## Locked Method

The target method is the dynamic `full_p3` topology:

- DS-SSM and PFIM are used together.
- The modified block is only the backbone P3/8 stage.
- Other backbone stages, neck, and detection head remain the Mamba-YOLO baseline.
- The implementation is in `source_code/work_train_single/ultralytics/nn/modules/mamba_yolo.py`.
- The clean P3 config is generated by `tools/run_sarmix_proxy.py` or
  `tools/run_sar4_full_suite.py` using `DS_VSSBlockSweep`.

Names that must not be confused with the locked P3 model:

| Candidate | Actual topology | Decision |
|---|---|---|
| `Mamba-YOLO-T-DS-SSM_Backbone-SSDD-ex7.yaml` | P2 | Historical only |
| `Mamba-YOLO-T-DS-SSM_Backbone-SSDD.yaml` | P2+P3 | Historical only |
| generated `full_p3` | P3 only | Locked target |
| `Mamba-YOLO-T-DS-SSM-OGSOD-pfim-full.yaml` | P2 | Not the locked P3 model |
| `Mamba-YOLO-T-DS-SSM_head-SSDD.yaml` | P2+P3 and modified head | Not a clean comparison |

For classification, segmentation, and change detection, "P3" means the
corresponding stride-8 backbone stage. The DS-SSM/PFIM equations and core module
must remain fixed, but task-specific integration code does not yet exist and
will require a separate adapter after Phase 0 approval.

## Existing Evidence and Duplicate-Run Audit

### Controlled result that can be retained

The strongest matched result currently recorded is OGSOD-1.0 TEST:

| Method | AP50 | AP75 | AP50:95 |
|---|---:|---:|---:|
| Mamba-YOLO-T | 0.771733 | 0.402109 | 0.423018 |
| IG-DS-SSM/PFIM-T | 0.772630 | 0.409711 | 0.436021 |

This is a matched single-run result and supports a localization-sensitive gain.

### SAR-Mix experiment that must not be repeated

The historical `sarmix_scratch_d16_v1` matrix already contains baseline,
DS-only, PFIM-only, global importance, and full placement records. Historical
Full P3 achieved overall AP50:95 `0.079592` versus baseline `0.070999`.
These are exploratory proxy results with unusually low aggregate metrics.
They can guide analysis but are not final paper results.

### Checkpoints that cannot be silently reused as Full P3

- SSDD PFIM ex27 exists locally and reports AP50:95 `0.74022`, but its topology,
  initialization, optimizer, and batch protocol are not matched to the locked
  dynamic Full P3 baseline pair.
- SAR-Aircraft historical checkpoints exist, but the available baseline and
  method runs use different optimization settings; the comparison is not a
  controlled P3 ablation.
- Historical SAR-Mix JSON files reference remote checkpoint paths. A metric JSON
  is not proof that a currently accessible checkpoint is available.
- The interrupted duplicate Full P3 run under `ds_ssm_sarmix_fast` is incomplete
  and must not replace the completed historical record.

Therefore, Phase 1 must first test checkpoint identity and config compatibility.
Only a checkpoint that exactly matches the locked Full P3 topology and evaluation
protocol may skip training.

2. Verify checkpoint/config hashes before deciding whether SSDD or SAR-Aircraft
   needs retraining.

   protocol; do not convert rotated labels silently.

5. Select one public change-detection baseline before implementing any adapter.
6. Define a leak-free patch split for the four one-pair change-detection datasets.
