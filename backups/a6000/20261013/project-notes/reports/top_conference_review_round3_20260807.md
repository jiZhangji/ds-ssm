# Part 1 [The Review Report]

## Summary

本文提出轻量级 IG-DS-SSM，通过局部残差抑制、空间重要性估计、因子化扫描驱动和动态步长调制改善 SAR 检测的高 IoU 定位质量，并以 OGSOD-1.0 同协议单次实验作为主要证据。

## Strengths

1. **核心主张与现有证据基本一致。** 论文没有把 OGSOD 上仅 `+0.090` 个百分点的 AP50 变化包装成普遍精度领先，而是聚焦 AP75 `+0.760` 和 AP50:95 `+1.300` 的定位敏感改善。SSDD、SAR-ShipDataset 和 SAR-Aircraft 被明确标为协议受限档案证据，避免了跨划分、跨优化器和中途变更 batch 的结果污染主要因果结论。
2. **代码与方法描述的对应关系进一步收紧。** 修订稿不再声称 gamma、write 和 delta 是三个独立循环更新位置，而是准确说明 gamma 与 write 共同因子化调制 CUDA scan drive，delta 位于独立的步长位置；PFIM 初始化对中心化驱动因子和未中心化 delta 的不同影响也被正确披露。这种实现透明度高于多数增量式结构论文。
3. **轻量化和失败案例具有实际价值。** T 级检测器约 5.96M 参数、13.21 GFLOPs，只替换一个浅层阶段；同时逐类别报告了 dense tank 的 AP50/AP75 退化，没有用总体均值掩盖方法边界。新增实验框架还能固定数据指纹、代码哈希、随机种子和 best-checkpoint TEST 规则，为后续可复现验证提供了扎实基础。

## Weaknesses (Critical)

1. **唯一主要同协议结果仍然只有单种子，当前 `+1.300` AP50:95 无法排除训练方差。** 论文没有 OGSOD baseline 与 full 模型在 seeds 0/1/2 上的原始结果、均值、标准差或按种子配对增量。对于约一个 AP 点的改进，这一缺口足以阻止“稳定提升”的结论。新增训练脚本不能替代已完成实验。
2. **核心结构必要性仍未被结果验证。** 当前没有同一提交下的 `Mamba-YOLO-T -> no-PFIM DS-SSM -> global-importance control -> token-wise PFIM` 四阶段对照，也没有 gamma-only、write-only、delta-only 和 gamma+write 的实际结果。因此无法判断收益来自局部 DWConv 残差抑制、任意额外门控、空间对齐的重要性场，还是 delta 调制。
3. **gamma 与 write 在 CUDA 快路径中的执行冗余削弱了“三分支创新”的独立性。** 两者最终以乘积 `gamma * w` 作用于同一 scan input，区别只来自函数形式和条件变量，而非不同状态更新位置。修订稿已经如实表述，但这也意味着论文必须用分支消融证明因子化参数化优于单一等参数 gate；否则该部分容易被评价为不必要的双重缩放。
4. **dense tank 退化仍只有现象描述，没有机制证据。** Tank 的 AP50 和 AP75 分别下降约 2.055 和 0.896 点，1,205 个实例集中于 71 张正样本图像。论文尚未按每图实例数、目标面积或最近邻距离分桶，也没有 PFIM 重要性图、重复实例粘连案例或 NMS 前后分析，因此“共享重要性场不利于实例分离”仍是未经验证的假设。
5. **跨数据集外部有效性仍主要依赖历史档案。** SSDD、SAR-ShipDataset 和 SAR-Aircraft 的趋势虽与定位改善一致，但都存在代码状态、训练过程或数据表示差异，不能证明方法跨数据集稳定有效。若 OGSOD 多种子结果波动较大，当前论文将缺少第二个受控数据集支撑主张。

## Rating

**6/10（边缘，偏弱拒稿）。** 方法轻量、问题定位合理且实现披露严谨，但 AAAI 级结构论文所需的多种子稳定性、核心消融和参数匹配替代对照仍没有实验结果，当前因果证据不足以支持稳定接收。

# Part 2 [Strategic Advice]

## 问题根源

第一、二项问题源于项目过去以跨服务器追求最佳单次结果为主，积累了大量性能记录，却没有围绕一个冻结提交设计最小因果矩阵。OGSOD 已经提供了合适的三划分和完整 baseline/full 运行，但单次结果只能证明“该设置下出现过提升”，不能证明结构本身稳定有效。当前新增的四阶段、三种子矩阵方向正确，真正缺少的是服务器完成结果。

第三项是方法结构本身需要正视的边界，而不只是措辞问题。CUDA 内核不暴露额外隐藏状态阻尼接口，因此 gamma 与 write 都只能进入 scan drive。两种函数形式可能形成有效的可解释因子化，也可能被单一 gate 等价替代；只有等参数 global control、单因子和组合消融才能区分这两种解释。论文已经删除了错误的“三个独立执行位置”表述，这修复了严谨性，但不会自动恢复新颖性。

第四项兼具实验和潜在方法缺陷。密集重复目标可能被局部残差抑制或共享重要性缩放削弱，也可能只是检测头、标签尺度或 NMS 的常见困难。没有密度分桶与可视化前，任何机制解释都只能写成假设。第五项则是历史数据资产的先天限制，不能靠重新措辞把非同协议比较变成受控消融。

## 可救性判断

多种子稳定性、四阶段主消融、gamma/write/delta 诊断和 global-importance 参数匹配对照都可以在修订期内解决，现有代码入口、自动 TEST 和汇总脚本已具备执行条件。这些实验不要求重新设计主模型，是当前最可救且最高优先级的缺口。

Dense tank 问题可以先通过离线分桶、重要性图和失败案例分析部分解决；若结果表明退化仅集中在极高密度样本，可以作为清晰边界而不必立即修改模型。若 full 在多数密度桶均低于 no-PFIM 或 global control，则属于结构性缺陷，必须弱化 PFIM 新颖性，甚至把主贡献转回 residual-suppressed DS-SSM。三个历史数据集的协议污染无法仅靠整理彻底修复，除非重跑至少一个第二受控数据集。

## 行动指南

1. 冻结当前提交和 OGSOD `dataset_snapshot.json`，完成 seeds 0/1/2 的 baseline、no-PFIM、global-PFIM 和 full 共十二次训练。只用 validation-selected `best.pt` 测一次 TEST，报告每个种子的原始值、均值、标准差和按种子配对的 AP50/AP75/AP50:95 增量。
2. 在同一提交下以 seed 0 完成 gamma-only、write-only、delta-only、gamma+write。正文必须称其为“因子化驱动与步长诊断”，不要重新使用“三个独立状态路径”的表述。
3. 将 global-PFIM 作为关键参数匹配对照：它与 full 参数量及可训练参数量完全一致，但将 token-wise importance 平均为图像级标量。若 full 稳定优于 global，才能支持“空间对齐重要性场”而非“多一个 MLP/gate”的贡献。
4. 对 OGSOD TEST 按每图实例数、框面积和最近邻中心距离分桶，分别比较 baseline/no-PFIM/global/full 的 AP50、AP75 和 AP50:95；展示至少两组 bridge/harbor 成功案例和两组 dense tank 失败案例，并可视化 P2/4 PFIM importance。
5. 若三种子 full 相对 baseline 的 AP50:95 均值增益接近或超过 1 点、标准差较小，且 full 优于 no-PFIM/global，则评分可提高到 7 分区间。若差值不稳定或 global 与 full 相当，应把贡献重心收缩为轻量 residual-suppressed DS-SSM，并把 PFIM 视为可选参数化，而不是核心创新。
