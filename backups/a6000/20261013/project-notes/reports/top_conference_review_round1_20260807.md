# Part 1 [The Review Report]

## Summary

本文提出面向轻量级 SAR 目标检测的 Importance-Guided De-Speckle State Space Model（IG-DS-SSM），以局部残差抑制和 PFIM 重要性估计联合调制 selective scan 的输入、写入门与步长，并试图证明其在约 5.96M 参数和 13.21 GFLOPs 下改善定位敏感指标。

## Strengths

1. **问题定位具体且具有领域意义。** 论文没有泛化地声称“把 Mamba 用于 SAR”，而是聚焦于斑点和背景散射进入序列状态后可能沿扫描方向传播的问题。局部残差抑制、二维局部方差和状态写入控制之间存在清晰的 SAR 任务动机。

2. **轻量化工作点有实际价值。** T 级模型约为 5.96M 参数、13.21 GFLOPs，且当前四个数据集的结果都更支持 AP50:95 而非 AP50 的提升。若能用严格受控实验确认，这会形成“几乎不增加复杂度但改善高 IoU 定位质量”的明确社区贡献，而不是依赖大骨干或扩散式检测流程。

3. **作者已主动暴露部分协议风险。** 稿件明确区分本地评估与 MaDiNet 文献结果，并说明 SAR-AIRcraft 切片协议、SAR-ShipDataset 未公开划分和 CUDA 快路径的实际实现。这种代码到论文的一致性意识优于多数初稿。

## Weaknesses (Critical)

1. **核心因果主张仍缺少同一不可变协议下的受控消融，这是当前最严重的问题。** SSDD 的方法与基线来自不同服务器或代码状态；SAR-ShipDataset 的基线在第 199 轮从全局 batch 256 改为 128；SAR-AIRcraft 的基线与方法在优化器、batch 和完成轮数上不同。因而这三组差值都不能单独证明收益来自 IG-DS-SSM/PFIM。当前也没有在相同初始化、数据顺序和训练策略下完成 `Mamba-YOLO-T -> DS-SSM -> DS-SSM+PFIM`，以及 PFIM 对 gamma/write/delta 三个分支的消融。对于以模块贡献为主的论文，这不是一般性的“实验略少”，而是论证链缺失。

2. **稿件遗漏了目前最有说服力的受控证据。** OGSOD-1.0 上的 Mamba-YOLO-T 与 PFIM-T 都完成 300 轮、采用同一 1024 输入、全局 batch 64、2 张 H200 和 AdamW，并在相同测试集上评估。PFIM-T 的 AP50:95 从 42.302 提升到 43.602（+1.300 点），AP75 提升 0.760 点，而 AP50 仅提升 0.090 点。该结果直接支撑论文应有的“高 IoU 定位改善”定位，却未出现在当前三数据集稿件中。

3. **PFIM 初始化描述与可执行代码不完全一致。** 稿件声称零初始化使 PFIM “以中性先验开始”，但代码只对 gamma 和 write 分支使用中心化的 `importance-0.5`；delta 分支使用原始 `importance`，在初始 `importance=0.5` 时会产生约 `0.5*eta` 的正偏置。因此，整个模块并非严格恒等或完全中性初始化。该问题主要是表述错误，不必重训，但若不修正会削弱代码可信度。

4. **结果揭示了尚未解释的密集重复目标失败模式。** OGSOD 测试集中 tank 类在 71 张正样本图像中包含 1,205 个目标，约每张 17 个；PFIM-T 相比基线的 tank AP50 从 52.257 降到 50.203，AP75 从 6.370 降到 5.474，而 bridge 和 harbor 明显提升。论文目前既没有密度分桶、尺度分桶或重要性图分析，也没有将结论限定到该失效条件。直接声称“增强小目标”会被反例否定。

5. **缺少多随机种子统计和参数匹配的通用替代对照，使方法新颖性与稳定性仍不足以达到 AAAI 稳定接收线。** 当前提升通常集中在 0.6--1.3 个 AP50:95 点，恰好属于随机波动必须被排除的量级。没有至少三个种子的均值与标准差，也没有“普通深度可分离平滑/等参数 MLP 门控/仅局部方差”等替代模块，审稿人无法判断收益来自提出的 SAR 状态控制，还是初始化、训练噪声或额外非线性。

## Rating

**5/10（边缘拒稿）。** 方法动机、轻量化价值和跨数据集趋势具有潜力，但当前版本尚未用受控消融与多种子统计建立核心因果结论；这是一篇可通过集中补实验和收缩主张修复的论文，而不是方法本身已经被证伪。

# Part 2 [Strategic Advice]

## 问题根源

第一项问题的根源不是模型结构天然无效，而是实验由多台服务器、不同代码快照和训练资源逐步恢复而来。作者拥有不少结果，但这些结果属于“外部有效性线索”，不能替代模块论文所需的内部因果验证。第二项问题则是论文冻结早于 OGSOD 完整评测，导致最干净的证据没有进入论证主线。二者共同造成一种反常状态：稿件展示了更多表格，却没有首先展示最能回答“模块是否有效”的实验。

第三项属于可直接修正的代码表述不一致。零初始化确实令重要性图处于非饱和的 0.5，且 gamma/write 的 PFIM 增量为零，但 delta 仍有小正偏置。把“整个模块中性”改为“重要性估计非饱和初始化；中心化分支中性；delta 带有小初始化偏置”即可，无需改变已有实验对应的实现。

第四项反映的是方法边界而非整类小目标缺陷。SSDD 船舶结果并不支持“PFIM 不适合小目标”的笼统结论；更精确的解释是，局部平滑和共享重要性控制可能在高度密集、外观重复、相邻散射中心相似时降低实例可分性。当前证据只能支持这一条件性假设，不能宣称已经找到机制原因。

第五项的深层原因是论文目前同时承担“新状态空间模块”“SAR 去斑先验”“跨数据集 SOTA/轻量化”三套叙事，但实验资源不足以同时证明三者。顶会论文不要求数学形式复杂，却要求贡献边界可归因。若主线收缩为“低复杂度下稳定改善定位敏感指标”，需要的证据更少，也更符合现有结果。

## 可救性判断

PFIM 初始化措辞、OGSOD 缺失、跨协议表格混排和过强结论都可在本轮改稿中完全解决。密集 tank 退化可以通过诚实报告、分层分析和可视化显著降低攻击面，但若要声称方法解决密集小目标，则必须修改模型并补实验，单靠写作无法修复。

受控三阶段消融与多随机种子是决定接收概率的关键补充。它们需要新增训练，无法由现有归档结果替代，但不要求改变方法。若时间只能支持一套完整实验，应优先在 OGSOD 或 SSDD 上固定代码提交，运行三个种子的 Mamba-YOLO-T、DS-SSM 和 DS-SSM+PFIM；分支消融可先用单种子作为机制分析。若这些结果不稳定，则应把论文降格为工程型轻量化研究，而不是继续强化因果措辞。

## 行动指南

1. 立即将摘要、贡献和结论统一改写为：IG-DS-SSM 在近乎不增加复杂度的条件下，主要改善 AP75/AP50:95 等定位敏感指标；不要声称所有数据集、所有类别或召回率均提升。

2. 将 OGSOD-1.0 作为主受控实验加入数据集、训练设置和测试结果。明确给出 baseline 与 PFIM-T 的同协议关系，并报告 bridge/harbor 获益、dense tank 的 AP50/AP75 下降。文献比较与本地配对实验必须分表或用清晰分组隔开。

3. 修正方法节初始化描述，保留当前与权重一致的公式 `Delta=softplus(W_delta u + eta I)`，不要为了文字上的“中性”把公式改成中心化重要性。说明 gamma/write 在 0.5 处无 PFIM 增量，而 delta 接收小的初始正偏置。

4. 在一个冻结的代码提交与数据清单上补 `Mamba-YOLO-T`、`DS-SSM without PFIM`、`full PFIM` 三阶段实验，每项至少三个随机种子。主表报告均值、标准差和最佳/最终 checkpoint 选择规则；不要再以不同服务器历史最优值构成消融表。

5. 增加机制消融：gamma only、write only、delta only、gamma+write、full；再增加一个参数量匹配的通用门控或仅 DWConv1D 对照。若预算有限，优先保证 full 与 no-PFIM 的多种子，分支消融可单种子并明确标记为诊断性实验。

6. 对 OGSOD 按每图实例数和框面积分桶，报告 AP50/AP75/AP50:95。至少展示 6--10 个 PFIM 成功与失败案例及重要性图，重点检查相邻 tank 是否被平滑或共同门控。没有这组分析时，只能把 dense repetitive objects 写成已观察到的局限，不能给出因果解释。

7. Rebuttal 中不要用 SAR-Ship 的 +8.25 AP50:95 作为首要证据，因为其 baseline 中途改变 batch。首要证据应是 OGSOD 的同协议 +1.30 AP50:95 和较低复杂度；SSDD、SAR-Ship 和 SAR-AIRcraft 作为跨数据集外部有效性证据，并主动标注协议限制。
