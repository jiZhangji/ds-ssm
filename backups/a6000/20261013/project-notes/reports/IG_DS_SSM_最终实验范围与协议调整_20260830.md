## 2. FUSAR-Map 统一分割协议

### 2.1 标签定义

FUSAR-Map 的 mask 中存在 black、red、green、blue、yellow 五种颜色。论文公开结果按四类地物计算，因此采用：

- 四种有效地物颜色映射为 class 0--3；
- black/unknown 映射为 `ignore_index=255`；
- black 不再作为第五个前景类别参与 mIoU、mPA、Dice 或 OA；
- 颜色到类别的最终映射必须由 mask 统计和原始标签说明共同确认，并写入固定 `class_map.json`。

### 2.2 数据划分与输入

- 使用 610 个 SAR/mask 配对；
- 按原始场景/区域 ID 划分，禁止把同一场景的相邻 tile 随机分到 train 和 test；
- 固定一份 manifest，建议 train/val/test 为 70%/15%/15%，所有方法完全共用；
- 训练阶段使用统一尺寸的 512 crop；验证和测试阶段拼接或逐 tile 评估，不能只对 crop 结果重复计数；
- 保持 SAR 数据的原始通道定义和动态范围；所有 baseline 与 P3 使用同一归一化和增强；
- 使用同一个分割框架接口实现 U-Net、DeepLabV3+、SegFormer 和 P3 版本，避免不同工程造成评价差异。

### 2.3 指标

主指标为 `mIoU`。同时报告：

- mPA；
- mean Dice；
- FWIoU；
- OA；
- 四个类别的 IoU；
- 有效像素比例和 ignore 像素比例。

旧的五类结果：baseline mIoU 21.084%、P3 mIoU 21.489%，只能作为历史诊断，不能与公开四类结果比较。修正后的四类 baseline/P3 必须重新生成完整结果 JSON。

## 3. 分类任务说明

### 3.1 MSTAR-SOC

使用经典 SOC：17° 俯角训练、15° 俯角测试，10 类车辆。实验应至少包含：

| 方法 | 作用 |
|---|---|
| ResNet18 | CNN 基线 |
| VMamba 或当前可运行的视觉 SSM 基线 | SSM 基线 |
| VMamba/SSM + IG-DS-SSM/PFIM | 本方法 |

指标只使用 Accuracy、Macro-F1、每类召回率和混淆矩阵。分类任务不使用 AP、AP50 或 mAP。

### 3.2 SAMPLE

SAMPLE 确实有公开方法，但大多数结果属于以下不同协议之一：

- 类增量识别，例如 RSPC 的 AIA；
- SAR 基础模型或预训练后线性探测；
- real/synthetic 混合方式不同；
- 类别数和训练/测试划分不同。

因此目前没有足够证据把这些结果与本项目闭集 Accuracy 直接排序。SAMPLE 应报告本项目 baseline/P3 的 Accuracy、Macro-F1、混淆矩阵，并把 RSPC、SARATR-X 等作为“协议不同的外部参考”，不能把 AIA 当作闭集 Accuracy。

## 4. 两个低分检测数据集的判断

### 4.1 SRSDD-v1.0

当前 HBB P3 结果为 AP50 48.339%、AP75 16.784%、AP50:95 22.147%，明显低于 GDB-YOLOv5s 论文的 HBB 结果 AP50 81.7%、AP50:95 47.6%。这不能直接说明 P3 失效，主要存在四类风险：

1. SRSDD 原始任务是 OBB，当前结果是把旋转标注转换为 HBB；转换规则、角点顺序和坐标归一化必须逐图检查；
2. 当前没有 matched Mamba-YOLO baseline，无法判断问题来自 P3 还是数据适配；
3. 数据只有 532 train / 134 test，六类细粒度舰船，类别不平衡和小目标影响很大；
4. GDB-YOLOv5s 使用 YOLOv5s、不同增强/训练策略和自己的数据处理，不能直接当作同协议上限。

重跑顺序应为：可视化 100 个 train/test 标签 -> 类别与框数量审计 -> HBB 转换单元测试 -> 同协议 YOLO/Mamba-YOLO baseline -> P3。若论文需要利用 SRSDD 的原始优势，应改为真正的 OBB 方案，不宜继续把 HBB 结果与 OBB 文献混排。

### 4.2 AIR-SARShip-2.0

当前 matched scratch 结果：baseline AP50:95 17.375%，P3 19.291%，只提升 1.916 个百分点。主要风险是：

1. 只有 300 张带标注图像、2,040 个实例，小样本方差很大；
2. TIFF 与 XML 的配对、文件名、坐标尺度和边界裁剪都经过转换，任一处错误都会同时拉低 baseline 和 P3；
3. SAR TIFF 可能存在 8/16 bit 动态范围差异，错误转成 uint8 会造成图像对比度严重丢失；
4. 外部 ImageNet-SSD、OSD-SSD、OSM-SSD、WBF-DM 使用预训练或融合，不能与当前 scratch 结果直接比较；
5. 单类舰船的小目标检测对输入尺寸、切片策略和增强非常敏感。

因此 AIR-SARShip-2.0 的第一步不是继续调模块，而是做图像显示、动态范围、XML 框叠加、空标注比例和 train/test 统计审计。baseline 也很低时，优先怀疑转换和协议；只有 baseline 正常而 P3 明显低，才归因于模型。

## 5. 论文实验矩阵规模

按当前精简范围，正式实验数量如下：

| 任务 | 数据集数 | 每个数据集的核心方法数 | 核心训练数 |
|---|---:|---:|---:|
| 目标检测 | 6 | Mamba-YOLO、P3 | 12 组，另加 SRSDD/AIR 数据审计重跑 |
| 分类 | 3 | CNN/SSM baseline、P3 | 6 组；MSTAR 为新增 |
| 语义分割 | 1 | U-Net/通用 baseline、P3 | 2 组核心，其他方法可作为补充 |
| 变化检测 | 2 | baseline、P3 | 4 组 |
| **合计** | **12** | - | **24 组核心训练** |

这 24 组不包含外部论文结果，也不包含数据审计后的必要重跑、可视化推理和复杂度测量。

## 6. 当前决策

1. 变化检测主实验只保留 Ottawa 和 Yellow River。
2. FUSAR-Map 采用四类有效标签、black=ignore 的协议；旧五类结果废弃为历史诊断。
3. 分类加入 MSTAR-SOC；SAMPLE 的公开结果只做协议说明，不强行排名。
4. SAR-ACD 保留，但分类只报告 Accuracy/Macro-F1，不再写 mAP。
5. 目标检测保留 SSDD、SAR-AIRcraft-1.0、SADD、AIR-SARShip-2.0、SRSDD-v1.0 和 SAR-ShipDataset。
6. SRSDD 与 AIR-SARShip-2.0 在重新训练前必须先完成数据和标签审计。
