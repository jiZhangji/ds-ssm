# Project Memory Rules

1. 先遵循当前平台、用户指令和适用项目规则，再读取本记忆入口。
2. 开始任务前读取 `PROJECT_STATE.md`、`TODO.md`、相关 `CONFLICTS.md`；按任务打开决策、实验、论文、代码结构和 `knowledge/`。
3. 不清空历史，不编造实验；区分事实、计划、推断、历史声称和未验证结果。
4. 技术决策记录背景、采用理由、替代方案和限制；失败实验记录现象及根因是否已验证。
5. 代码、论文或实验实际改变后，按授权更新相关状态和证据；纯问答没有新事实时不为形式重复改文件。
6. 保留旧状态的时间线和来源，再定点更新当前状态；任务完成必须有完成标准和证据。
7. 多 AI 共用同一 project-id 和记忆根目录，写入前检查并发；不能获得可靠锁时保存为独立批次并报告待合并。
8. 凭据不落盘到记忆；命令中的认证信息使用占位符；不复制外部附件中的秘密。
9. 能从项目文件解决的问题先查文件；只有真实缺口才询问用户。
10. 项目目标或范围变化时保留旧决定和变化原因，状态中展示现行版本。
11. 修复记忆结构时保留旧布局入口和链接，不移动业务文件。
12. 无权限、缺原件或未验证结果必须明确报告，不能声称仅靠记忆完成运行验证。

敏感信息过滤范围包括密码、API Key、access/refresh token、Cookie、私钥、数据库凭据、认证 URL 和不必要的个人身份信息。新文件只可使用 `[已配置，已脱敏]` 或 `<REDACTED:类型>`。
